## 2. Поиск и описание данных

- **Источник данных:** как нашли датасет, ссылка, почему выбрали именно его
Датасет найден на платформе Kaggle (https://www.kaggle.com/datasets/wereouma/the-telco-churn-xls). Он был выбран, так как является классическим и отлично структурированным набором данных реального бизнеса, содержащим данные о поведении клиентов мобильной связи, включая финансовые показатели, статистику звонков и уровень удовлетворенности.
- **Описание датасета:**
  - Объём: 20000 строк и 13 столбец
  - Описание признаков (типы, смысл): ID: уникальный идентификатор клиента (будет удален). COLLEGE: наличие высшего образования (категориальный: zero, one). INCOME: годовой доход клиента (числовой). OVERAGE: перерасход минут/услуг в месяц (числовой). LEFTOVER: остаток неиспользованных минут в месяц (числовой). HOUSE: оценочная стоимость недвижимости клиента (числовой). HANDSET_PRICE: стоимость телефона клиента (числовой). OVER_15MINS_CALLS_PER_MONTH: количество звонков дольше 15 минут (числовой). AVERAGE_CALL_DURATION: средняя продолжительность звонка (числовой). REPORTED_SATISFACTION: заявленный уровень удовлетворенности (категориальный). REPORTED_USAGE_LEVEL: заявленный уровень использования связи (категориальный). CONSIDERING_CHANGE_OF_PLAN: рассматривает ли клиент смену тарифа (категориальный). Целевая переменная: LEAVE (STAY — остался, LEAVE — ушел).
  - Объем данных (20 тыс. строк) является вполне достаточным для стабильного обучения большинства алгоритмов машинного обучения.

## 3. Обработка и подготовка данных

- **Полная очистка:**
  - Пропуски: Произведена проверка на пустые значения. В случае появления пропусков реализована стратегия заполнения: для числовых признаков — медианой (устойчивость к выбросам), для категориальных — модой.
  - Дубликаты: Поиск полных дубликатов строк показал их отсутствие. Столбец ID был удален, так как является уникальным идентификатором и не несет предсказательной силы.
  - Выбросы: Анализ Boxplot-графиков показал, что в исходных числовых признаках экстремальные выбросы отсутствуют. Дополнительная обработка выбросов не потребовалась.
  - Типы данных: Целевая переменная LEAVE преобразована в бинарный формат (LEAVE -> 1, STAY -> 0).
- **Работа с фичами:**
  - Исходное количество признаков: 11 (без учета ID и Target). После применения One-Hot Encoding категориальных переменных размерность составила 20 признаков.
  - Новые фичи, feature engineering (созданы 3 новые фичи для будущего использования):
  1. `Income_per_House`: отношение дохода к стоимости дома (INCOME / HOUSE). Показывает уровень финансовой нагрузки клиента.
  2. `Has_Overage`: бинарный флаг (1/0), показывающий наличие любого перерасхода связи (OVERAGE > 0).
  3. `Total_Long_Calls_Duration`: произведение количества долгих звонков на их среднюю продолжительность.
- **Визуализации:** графики, отражающие распределения, зависимости между признаками и целевой переменной
Построенные графики выявили мультиколлинеарность (сильная связь INCOME и HANDSET_PRICE). Анализ `REPORTED_USAGE_LEVEL` показал, что заявленный уровень использования связи почти одинаков у уходящих и остающихся клиентов, что говорит о слабой предсказательной силе этого признака. Также графики показали почти идеальный баланс классов, что снимает проблему несбалансированных выборок.
- **Сплит данных:**
  - Данные разбиты на train / val / test в соотношении 70% / 15% / 15%. Использован параметр `stratify=y` для точного сохранения баланса классов во всех подвыборках. Установлен фиксированный `random_state=42` для воспроизводимости.
  - Трансформеры для масштабирования (StandardScaler) и кодирования категорий (OneHotEncoder) обучались строго на тренировочной выборке. К валидационной и тестовой выборкам применялся только метод `.transform()`.

## 4. Baseline-модель

- **Модель:** В качестве простой модели «из коробки» выбрана Логистическая регрессия (Logistic Regression). Для чистоты эксперимента и соблюдения требований к baseline, перед обучением из данных были удалены 3 сгенерированных признака (feature engineering). Модель обучалась на 20 базовых признаках
- **Результаты:** 
  - **Validation:** 
    - ROC-AUC: 0.6977
    - F1-score: 0.6279
    - Accuracy: 0.6413
    - Precision: 0.6421
    - Recall: 0.6143
  - **Test:** 
    - ROC-AUC: 0.6987
    - F1-score: 0.6313
    - Accuracy: 0.6433
    - Precision: 0.6433
    - Recall: 0.6198
- **Цель:** Метрики на валидационной и тестовой выборках практически идентичны, что доказывает отсутствие переобучения. Значение ROC-AUC ~0.70 является точкой отсчёта. Линейная модель уперлась в свой предел из-за наличия мультиколлинеарности и нелинейных зависимостей в данных. Эта метрика будет использоваться для сравнения с более сложными ансамблевыми алгоритмами на следующем этапе, куда также добавятся сгенерированные признаки для повышения качества.
